# Отчёт по договорам: работы, выплаты, остатки

Скрипт читает три CSV из папки `data/` и строит отчёт на указанную дату:
по каждой работе — цена, выплачено, осталось; и итоги по каждому договору.

## Запуск

Нужен только Python 3.10+ (внешние библиотеки не требуются).

```
python3 report.py --date 2026-11-10
```

По умолчанию данные берутся из `./data`, отчётная дата — `2026-11-10`.
Можно указать явно:

```
python3 report.py --data data --date 2026-11-10
```

## Проверки

```
python3 -m unittest test_report -v
```

Девятнадцать проверок: цифры на 10.11.2026 и разнесение аванса по работам, статусы и суммы
на разные даты (05.09, 01.10, 10.11, 12.11), возврат и отмена по датам, поздние операции,
инварианты (сумма по работам = выплаты, выплата по работе не больше цены), деньги в Decimal,
обработка некорректной даты в CLI, а также устойчивость к мусорным данным: нечисловая сумма,
отсутствующий файл или колонка, пустые даты, платёж из чужого договора.

## Что в репозитории

| Файл | Что это |
|---|---|
| `report.py` | скрипт отчёта |
| `test_report.py` | тесты |
| `DECISIONS.md` | принятые решения: что решал, какие были варианты, что изменится, если неверно |
| `ЗАПИСКА_БУХГАЛТЕРУ.md` | пояснение для бухгалтера |
| `data/` | исходные CSV (договоры, работы, платежи) |

## Как считается

- деньги — `Decimal`, округление до копейки;
- в выплаты попадают платежи со статусом `paid` с датой платежа до отчётной даты
  (если `paid_at` пуст — берётся `created_at`, с предупреждением);
- возврат (`refunded`) считается выплатой до даты возврата и исключается из выплат
  начиная с `refunded_at`; после этого показывается строкой «возвращено подрядчиком»;
- `queued` (в очереди) в выплаты не входит и показывается отдельной строкой;
- статус работы определяется на отчётную дату по `completed_at` / `cancelled_at`;
  если дата не указана, используется статус из выгрузки — с предупреждением;
- отменённые на отчётную дату работы не участвуют в сумме к оплате;
- авансы без привязки к работе разносится по работам по принципу FIFO — сначала выполненные
  по дате приёмки, затем запланированные (подробнее в `DECISIONS.md`, пункт 4).
